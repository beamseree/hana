The original unreproduced top-left minimization observation and #8's earlier foreign-input failure remain observations with unknown causes; this fix is not attributed to either.

### Earlier indexed-search timing failure (superseded assessment)

Final isolation checks after the physical run strengthen, rather than remove, the limitation. An idle five-second heartbeat in the same SwiftPM harness recorded 810 samples, maximum excess **4.31 ms**, zero above 50 ([control](idle-timing-control.txt)); it used the same 5 ms `Task.sleep` loop without Search and was removed afterward. The original indexed test then failed at **252.14 ms** in debug and **89.78 ms** with `-c release` ([debug](responsiveness-post-fda-debug.txt), [release](responsiveness-post-fda-release.txt)). Thus debug overhead alone does not explain the recurrence. Temporarily reducing the metadata copy chunk from 128 to 16 did not fix it (**355.02 ms**); that experiment was reverted ([output](chunk16-experiment.txt)). Disabling only the file source in the test and dropping its file-presence assertion passed the unchanged 50 ms bound ([local-only control](local-only-timing-control.txt)); the production code and original test were restored afterward.

These controls narrow the observed failure to indexed-search work in this test environment. The [short profile](profile-recurrence-excerpt.txt) contains path-lookup mutex waits but is not timestamp-correlated with the largest delay. No sole cause or safe remaining fix is established. The positive installed-app runs use a different identity/lifecycle, debounce and polling workload, so they do not invalidate the failing test. **The indexed responsiveness acceptance gap is unresolved**, and remains a reason to keep #10’s PR draft. The earlier synchronous type-fetch defect was reduced; the overall no-stall requirement is not declared fixed. No helper or batch-size workaround is retained.
