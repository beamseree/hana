## Safety incident and limitation

Before the no-argument bundle guard existed, CUA `getApp(path)` unexpectedly auto-launched the isolated bundle without CLI arguments and timed out. That owned fixture PID44216 was terminated; installed PID9148 was untouched. That binary could attempt normal live startup, so **no-live-attempt cannot be claimed for this incident**. No direct refusal log was captured. A later [read-only ownership check](live-ownership-check.txt) found installed PID9148 alive with one Collection directory descriptor and nonblocking exclusive ownership refused. For an existing Collection, source obtains OwnerLock before SQLite validation/open/migrations; fresh missing-Collection initialization precedes that lock. These facts support protection of the already-owned collection but do not establish an observed refusal by PID44216. The corrected signed bundle now refuses no-args before AppKit; subsequent CUA only bound the process launched with fixture arguments. No live content was read or logged by this investigation.
