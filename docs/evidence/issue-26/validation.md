## Test runs

- Source for every recorded run: `44da963` (clean tree). [Build](build.txt): signed ad-hoc `com.beamseree.hana`.
- Full deterministic suite, `xcrun swift test --no-parallel`: 101 tests in 13 suites passed in 13.9 s, including the environment-sensitive `NativeEditingTests`. That is 16 new tests: 12 in `TaskLifecycleTests` and 4 in the harness suite, plus the live-root refusal test extended to task actions. [Output](full-tests.txt).
- Harness suite against the signed release binary: 12 tests passed, 31 cases with the kill matrices. [Output](signed-harness-tests.txt).
- Mutation checks during development: dropping placement from the creation digest, and restoring a completed task into Inbox, each made the idempotence, matrix or observation tests fail.
- Code review found that a harness creation retry hung once the item had left its observed list: a completed, archived or moved task, or an archived note. A new test reproduced the hang. The harness now waits only while the item belongs in that list. The Store was not affected.

## Decisions and limitations

- Version 1's schema checks the title subset LF, CR, NEL, U+2028 and U+2029. The commands also refuse VT and FF, the other Unicode mandatory breaks. Adding them to the schema would change version 1, which needs its own bounded decision.
- A completed, unarchived task can be renamed. Only archived tasks refuse edits.
- Renumbering at key exhaustion changes other tasks' order keys without changing their revision or updated time, because their relative order and facts are unchanged. There is no list revision yet. The stale-list precondition for manual reorder belongs to #27.
- Search projection flags are independent: an archived completed task appears only when both `includingCompleted` and `includingArchived` are set.
- Timestamps come from the Store clock at submission and aren't forced to be monotonic, as in #25.
- Export (#28), snapshots (#29), manual reorder (#27), capture UI and organizer UI are not implemented.
- This is process-crash and restart evidence only, not power-loss evidence, as in #24.
